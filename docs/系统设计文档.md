# forest 系统设计文档

用大白话说清楚：这是什么、怎么跑起来、数据怎么走。

---

## 一、这个系统是什么

**一句话：给企业做一个"能问文档的智能客服"。**

用户上传 PDF/Word/Markdown 文档 → 系统自动解析、切碎、向量化 → 用户提问时，系统先检索相关文档内容 → 交给大模型生成带引用的回答。

它解决三个问题：
1. **幻觉**：大模型不会瞎编，答案必须来自真实文档，证据不足就拒绝回答
2. **知识割裂**：企业文档分散各处，统一管理、统一检索
3. **无记忆**：多轮对话记住上下文，不是每次都是陌生人

## 四、核心技术选型（为什么选这些）

| 组件 | 选型 | 原因 |
|------|------|------|
| 后端框架 | FastAPI | 原生 async，性能好，自动文档 |
| ORM | SQLAlchemy 2.0 async | 类型安全，async 支持好 |
| 主数据库 | PostgreSQL 16 | 成熟稳定，JSONB 灵活 |
| 向量检索 | pgvector（HNSW索引） | 和 PG 同库，事务一致，无需额外运维 |
| 关键词检索 | Elasticsearch 8 + IK分词 | BM25 精确匹配，IK 中文分词 |
| 文件存储 | MinIO | S3 兼容，支持分片上传 |
| AI 框架 | LangGraph | 状态机建模 Agent，比 LangChain 更可控 |
| 前端框架 | Vue 3 + TypeScript | 生态好，类型安全 |
| UI 组件 | Element Plus | 中文友好，管理后台开箱即用 |

## 五、三大核心流程（数据怎么流动）

### 流程 1：文档入库（用户上传到可检索）

```
用户上传 PDF
     │
     ▼
┌─────────────────┐
│  MinIO 存储原件  │  ← 原始文件存在这里
│  （SHA-256 去重）│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  文档解析        │  ← Docling / MinerU（PDF）
│  （按格式选择    │     python-docx（Word）
│   不同解析器）   │     直接读（MD/TXT）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  文本清洗        │  ← 去空白、去特殊符号
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  语义切块        │  ← 按结构切，目标240token，
│  （重叠32token） │     相邻块有重叠不丢上下文
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐  ┌──────────┐
│存入PG │  │存入ES    │
│向量表 │  │全文索引  │
│(pgvector)│ │(BM25+IK)│
└───────┘  └──────────┘
```

关键设计：
- **SHA-256 去重**：同组内相同文件不重复处理
- **状态机**：UPLOADED → PROCESSING → READY（成功）或 FAILED
- **失败可重试**：管理员在控制台点"重试"即可重新走 ETL

### 流程 2：知识库问答（用户提问到得到答案）

```
用户提问："公司差旅报销标准是什么？"
     │
     ▼
┌──────────────────────┐
│ ① 查询规划（LLM）    │  ← 分析用户意图
│ 策略：DIRECT/         │     决定用一条还是多条查询
│        REWRITE/       │
│        DECOMPOSE      │
└──────────┬───────────┘
           │
           ▼ 并行执行
┌──────────────┐  ┌──────────────┐
│ pgvector     │  │ Elasticsearch│
│ 语义检索     │  │ 关键词检索   │
│ （意思相近）  │  │ （包含精确词）│
└──────┬───────┘  └──────┬───────┘
       │                 │
       └────────┬────────┘
                ▼
┌──────────────────────┐
│ ② RRF 融合排序       │  ← 1/(60+rank) 加权合并
│ 双通道都命中的得分翻倍│     取 Top 8
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ ③ 证据等级评估       │  ← NONE / WEAK / PARTIAL / SUFFICIENT
│ 相似度<0.65 → NONE   │     NONE 直接拒答，不调 LLM
└──────────┬───────────┘
           │
    ┌──────┴──────┐
    │ 证据不足？   │
    ▼             ▼
  拒答          ④ LLM 生成
  （不发请求）   │ 把证据+问题+等级指令
                │ 一起发给大模型
                ▼
          ┌──────────────┐
          │ SSE 流式输出  │  ← 打字机效果
          │ <<<ANSWER>>>  │     前端实时渲染
          │ <<<END>>>     │
          └──────┬───────┘
                 │
                 ▼
          落库（问答历史）
```

关键设计：
- **证据不足直接拒答**：节省 LLM 调用成本，避免胡编乱造
- **SSE 流式**：用户立即看到文字逐字出现，不觉得卡在等待
- **引用溯源**：答案附带来源文档名和片段，用户可以点击查看原文

### 流程 3：AI 助手（多轮对话 + 工具调用）

```
用户发消息："帮我查一下最近的销售报告"
     │
     ▼
┌──────────────────────────┐
│ LangGraph ReactAgent     │  ← 自主决定做什么
│                           │
│ 每轮循环：                │
│ ① LLM 思考               │
│ ② 决定调工具 or 直接回答  │
│    ├─ 调知识库检索工具    │
│    ├─ 查文档列表          │
│    └─ 直接回答用户        │
│ ③ 拿到结果继续下一轮      │
│ （最多10轮，防死循环）    │
└───────────┬──────────────┘
            │
     ┌──────┴──────┐
     ▼             ▼
  调工具        直接回复
  （查PG/ES）   （流式返回前端）
     │
     ▼
┌──────────────────┐
│ 短期记忆管理      │
│ >20条消息 或      │
│ >8000字符 →      │
│ LLM 摘要压缩      │
│ （保留上下文）    │
└──────────────────┘
```

关键设计：
- **ReactAgent**：LLM 自主决定调不调工具，不是固定流程
- **记忆摘要**：对话太长时自动压缩，省 token 不丢上下文
- **会话归档**：30天不活跃自动归档，界面清爽

## 六、多租户数据隔离（小组之间数据不串）

每个用户属于一个或多个"小组"，数据按小组隔离：

```
用户A ──┐
        ├─→ 小组1 ──→ 文档集合 ──→ pgvector（WHERE group_id=1）
        │                    └─→ ES索引（WHERE group_id=1）
用户B ──┘

管理员 ──→ 可跨所有小组操作
```

隔离有三层保障：
1. **查询层**：所有 SQL 都带 `WHERE group_id = :gid`
2. **权限层**：`require_group_access()` 校验当前用户是否属于该组
3. **引擎层**：pgvector 的 `cmetadata->>'group_id'` 和 ES 查询都携带 group_id

## 七、启动步骤（5分钟跑起来）

```bash
# 1. 启动基础设施（PostgreSQL + MinIO + ES）
docker compose up -d

# 2. 配置后端（复制模板，填入自己的 API Key）
cd forest-backend
copy .env.example .env
# 编辑 .env：填入 DeepSeek/通义千问的 API Key

# 3. 初始化数据库（创建表 + 种子管理员）
pip install -r requirements.txt
python init_db.py

# 4. 启动后端（端口 10001）
uvicorn app.main:app --host 0.0.0.0 --port 10001 --reload

# 5. 启动前端（端口 5173）
cd ../forest-frontend
npm install
npm run dev
```

访问 http://localhost:5173，默认管理员：`admin` / `Admin@123456`

## 九、部署架构（生产环境）

```
                    ┌─────────────┐
                    │   Nginx     │  ← 反向代理 + HTTPS
                    │  (:80/:443) │
                    └───┬─────┬───┘
                        │     │
              ┌─────────▼┐  ┌─▼─────────┐
              │  前端静态  │  │ FastAPI   │  ← 可多实例横向扩展
              │  文件     │  │  (10001)  │
              └───────────┘  └────┬──────┘
                                   │
                    ┌──────────────┼──────────────┐
                    ▼              ▼              ▼
              ┌──────────┐  ┌──────────┐  ┌──────────┐
              │PostgreSQL│  │Elastic-  │  │  MinIO   │
              │+pgvector │  │search    │  │  (文件)  │
              │  (主从)   │  │ (集群)    │  │  (多副本) │
              └──────────┘  └──────────┘  └──────────┘
```

生产加固要点：
- 关掉 `DEV_ADMIN_ENABLED`，不允许自动创建管理员
- ES 开启 xpack 安全认证
- MinIO 开启 HTTPS
- 数据库密码从环境变量注入，不硬编码
- 加上 Redis 做分布式锁（当前是单实例）
