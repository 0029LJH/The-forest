**17. 写操作升级为 interrupt 硬确认（human-in-the-loop）**
- 背景：对话确认（Agent 文字询问"请确认？"）用户不满意，期望界面确认按钮
- 机制：写工具（ban_group/unban_group/delete_document）内部 `interrupt({type/action/target/impact})` 暂停图执行 → SSE 发 `confirmation` 事件 → 前端确认卡片（确认执行/取消按钮）→ 用户点击后再次请求 stream 带 `resume: "confirm"/"cancel"` → LangGraph `Command(resume=...)` 恢复 → 工具继续执行
- 改动：
  - `tools.py`：3 个写工具 + `_confirm_interrupt` 辅助（interrupt 返回确认信息）
  - `facade.py`：中断检测改读 `state.tasks[].interrupts`（langgraph 1.2 API，非 state.values）；`chat_stream` 支持 resume 参数（`Command(resume=...)` 恢复）
  - `service.py`：resume 分支跳过 USER 消息保存/记忆维护；被中断的首次流不落空 ASSISTANT 消息；ADMIN 指令改为"写操作直接调用工具，不要文字确认"
  - `schemas.py` / `router.py`：ChatRequest 加 resume 字段并透传
  - 前端：`confirmation` 事件 → 确认卡片（琥珀色警告 + 确认/取消按钮）；`resumeInterrupted()` 再次 stream 绑定同一消息；types 加 `AssistantConfirmation`
- 排查过程：interrupt 触发但图未暂停的假象——实际图暂停正常（`state.next=('tools',)`），是中断信息读取 API 用错（langgraph 1.2 在 `state.tasks[].interrupts`）
- 验证（_test_confirm.py）：① 暂停生效（confirmation 事件 + 群组保持 ACTIVE）② resume confirm 执行（DISABLED）③ resume cancel 不执行（保持 DISABLED）④ 环境还原；全部通过
